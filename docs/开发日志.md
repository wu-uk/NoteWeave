# NoteWeave 开发日志

## 2026-06-02

目标：
建立项目开发规范，并完成后端 MVP 首个可运行切片。

完成：
1. 新增 `docs/项目规范文档.md`，约定长期 goal 模式、git 检查点、uv 环境、开发日志和验证方式。
2. 安装 `python3.14-venv`，在项目内创建 `.tools/uv`，并安装 `uv 0.11.17`。
3. 新增 `.gitignore`，排除 `.venv/`、`.tools/`、`.uv-cache/`、运行数据库、缓存和前端构建产物。
4. 新增 `backend/pyproject.toml`，后端使用 uv 管理依赖。
5. 新增 `backend/src/noteweave/` 后端包，完成 FastAPI + SQLite 轻量后端。
6. 首版接口覆盖注册登录、课程、成员、知识树、笔记、版本、错题、评论、点赞/收藏、补充/纠错、关键词检索、AI 摘要和标签建议。
7. AI 当前是本地规则降级实现，不依赖真实模型 API；后续可替换为远程 OpenAI-compatible client。
8. 新增 `backend/tests/test_mvp_flow.py`，覆盖课程笔记协作核心闭环。

验证：

```bash
cd /root/project/NoteWeave/backend
env UV_CACHE_DIR=/root/project/NoteWeave/.uv-cache ../.tools/uv/bin/uv run --no-sync pytest
```

结果：

```text
1 passed in 1.32s
```

注意：
1. 当前环境中 `uv` 不在系统 PATH，使用项目内 `../.tools/uv/bin/uv`。
2. uv 默认缓存目录 `/root/.cache/uv` 当前不可写，命令需要设置 `UV_CACHE_DIR=/root/project/NoteWeave/.uv-cache`。
3. `uv run pytest` 会尝试同步依赖并联网；依赖已安装时使用 `uv run --no-sync pytest`。
4. 当前 FastAPI/Starlette 在 Python 3.14 环境中同步路由/同步依赖会挂起，因此后端 API 路由和 FastAPI 依赖函数均使用 `async def`。

遗留：
1. 还没有前端应用。
2. 后端暂用标准库 SQLite repository，后续可按架构文档演进到 SQLAlchemy/SQLModel。
3. AI 模块还没有接入远程模型 API。
4. 文件上传、图片附件和富文本编辑器尚未实现。
5. 当前测试只有一条端到端 MVP flow，后续需要拆分更多权限和异常场景测试。

下一步：
1. 提交后端首个开发检查点。
2. 补充根 README 的运行说明。
3. 继续实现前端课程工作台或完善后端文件/附件能力。

目标：

## 2026-06-02 图片附件切片

目标：
补齐笔记和错题所需的轻量图片上传、预览和正文插入能力。

完成：
1. 新增 `attachments` 表，记录课程、可选笔记/错题关联、原始文件名、存储文件名、类型、大小和访问路径。
2. 新增 `POST /api/attachments`，使用 JSON base64 上传图片，避免引入 `python-multipart` 等额外依赖。
3. 新增 `GET /api/files/{stored_name}`，按不可猜测存储名读取图片，返回可直接用于 Markdown 图片引用的 URL。
4. 配置新增 `NOTEWEAVE_FILE_STORAGE_DIR` 和 `NOTEWEAVE_MAX_UPLOAD_BYTES`，默认保存到后端 `uploads/`，默认限制 5 MiB。
5. 前端笔记正文和错题题干新增图片选择、上传、预览，并把返回的 `![name](url)` 插入文本框。
6. 集成测试覆盖图片上传、文件读取、Markdown 写回笔记。
