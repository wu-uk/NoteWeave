## 2. 项目背景

在日常课程学习中，学生会持续产生笔记、作业订正、错题总结、实验记录、复习资料、课堂截图、群聊文件等学习资源。这些资源通常分散在 Word 文档、Markdown 文件、手机备忘录、纸质笔记、截图和聊天记录中，缺少统一整理与共享机制。

当前常见笔记工具大多偏向个人记录，虽然能够完成基本编辑，但在课程学习场景中存在以下问题：

1. 资料归档困难：笔记通常以线性文档保存，缺少与课程章节、知识点、题型之间的明确对应关系。
2. 共享协作不足：不同同学手中存在大量优质笔记、订正和理解补充，但缺少面向班级或小组的协同沉淀渠道。
3. 检索粒度较粗：传统关键词搜索通常只能定位到某篇文档，难以直接定位到具体章节、知识点、题目或段落。
4. 知识复用率低：课程资料无法持续沉淀，临时笔记难以演变为可维护、可复用的课程知识资产。

因此，需要建设一个面向课程学习场景的课程笔记协作系统，以“章节化组织、多人协作共创、AI 辅助处理、精细化检索”为核心，帮助学生把分散资料沉淀为结构化、可共享、可持续维护的课程知识库。

## 3. 项目目标

### 3.1 总体目标

开发一个可运行、可演示的课程笔记协作系统，实现课程笔记的录入、分类、共享、检索和复习支持，提升日常学习和考前复习效率。

### 3.2 具体目标

1. 实现课程与章节管理，使笔记能够按课程、章节和知识点进行组织。
2. 实现支持富文本编辑的笔记编辑器，支持文本、标题、列表、代码块、LaTeX 公式、图片和思维导图等内容。
3. 实现错题笔记整理功能，支持作业、练习和测试中的错题归类、复盘与复习。
4. 实现协作共享功能，支持同学上传笔记，并进行点赞、评论、补充和纠错。
5. 实现 AI 摘要生成和关键词标签提取，帮助用户快速把握长笔记核心内容。
6. 实现面向知识点的智能检索，使用户能够快速定位到相关笔记内容。
7. 构建课程知识树，用层次化方式展示课程内容，提高系统可维护性和扩展性。

### 3.3 预期成果

1. 一个可演示、可运行的课程笔记协作系统原型。
2. 一套完整的系统设计文档、数据库设计文档和用户说明文档。
3. 项目演示 PPT 和课程答辩材料。
4. 后续可扩展为适用于多门课程的学习辅助平台。

## 4. 用户角色

| 角色 | 说明 | 核心权限 |
| --- | --- | --- |
| 普通学生 | 系统主要使用者，负责浏览、创建、补充和复习课程笔记 | 加入课程、查看共享笔记、创建个人笔记、提交共享笔记、评论、点赞、收藏、检索 |
| 课程维护者 | 负责课程知识树维护和内容质量管理，可由小组成员或班级负责人担任 | 创建课程、维护章节和知识点、处理纠错、管理共享内容、调整标签 |

| 系统管理员 | 负责系统级配置和账号管理 | 用户管理、课程管理、系统配置、AI 接口配置、数据维护 |

## 5. 需求范围

### 5.1 MVP 范围

MVP 版本应优先形成“课程创建 -> 章节组织 -> 笔记编辑 -> 共享互动 -> 检索复习”的核心闭环，至少包含：

1. 用户注册、登录与基础身份管理。
2. 课程创建、加入、退出与课程列表。
3. 课程章节和知识点树的创建、编辑、排序和查看。
4. 笔记创建、编辑、保存、归档和查看。
5. 错题笔记录入、分类和复习查看。
6. 共享笔记浏览、点赞、评论、补充和纠错。
7. 关键词、章节、标签和知识点检索。
8. AI 摘要生成和关键词标签提取的基础能力。

### 5.2 后续增强范围

1. 多门课程的统一学习空间。
2. 相似错题推荐和知识点关联推荐。
3. 课程知识图谱或更复杂的节点关系展示。
4. 更完善的版本对比、内容审核和贡献统计。
5. 全文检索引擎、向量检索或混合检索。
6. 移动端适配或独立移动应用。

### 5.3 非本期重点

1. 实时多人同屏协同编辑。
2. 教学评分、作业批改和考试系统。
3. 商业化课程市场或公开社区分发。
4. 复杂组织架构、跨学校权限体系。

## 6. 核心业务对象

系统采用结构化节点存储模式，核心层级为：

```text
课程 -> 章节 -> 知识点 -> 笔记 / 错题 / 标签 / 补充说明
```

| 对象 | 说明 |
| --- | --- |
| 用户 | 使用系统的学生、维护者、教师或管理员 |
| 课程 | 学习资源组织的一级空间，例如“数据结构”“软件工程” |
| 章节 | 课程下的目录节点，例如“排序算法”“需求分析” |
| 知识点 | 章节下的细粒度学习节点，例如“快速排序时间复杂度” |
| 笔记 | 挂载在课程、章节或知识点下的学习内容 |
| 错题 | 带有题目、答案、错误原因和反思的特殊笔记 |
| 标签 | 用于标识主题、题型、难度、考试重点等信息 |
| 评论 | 对笔记、错题或纠错建议的讨论内容 |
| 纠错 | 对已有内容提出修改建议或错误反馈 |
| 补充 | 对已有知识点或笔记增加新的解释、例题或资料 |
| 版本记录 | 笔记和知识节点变更的历史留痕 |
| AI 结果 | 自动生成的摘要、关键词和标签建议 |

### 7.1 用户与权限管理

| --- | --- | --- |
| FR-001 | 用户应能够注册账号并登录系统。 | P0 |
| FR-002 | 用户应能够查看、修改个人基础信息。 | P1 |
| FR-003 | 系统应支持普通学生、课程维护者、教师/助教、系统管理员等角色。 | P1 |

## 8. 关键业务流程

### 8.1 创建课程与知识树

1. 用户登录系统。
2. 创建课程并填写课程名称、简介和学期信息。
3. 系统为创建者分配课程维护者权限。
4. 课程维护者创建章节和知识点。
5. 系统生成课程知识树。
6. 课程成员通过课程入口浏览知识树。

### 8.2 创建并归档笔记

1. 用户进入课程。
2. 选择章节或知识点。
3. 打开笔记编辑器。
4. 输入标题和正文，插入代码块、公式、图片或思维导图。
5. 选择可见性和标签。
6. 保存为草稿或发布到课程共享区。
7. 系统记录作者、归属节点、更新时间和版本信息。

### 8.3 协作补充与纠错

1. 用户浏览某一共享笔记。
2. 用户发现可补充内容或错误内容。
3. 用户提交补充或纠错建议。
4. 笔记作者或课程维护者查看建议。
5. 处理人为建议选择采纳、拒绝或继续讨论。
6. 系统记录处理结果和版本变化。

### 8.4 AI 摘要和标签提取

1. 用户打开长笔记。
2. 用户触发 AI 摘要或标签提取。
3. 系统调用大模型接口处理笔记内容。
4. 系统展示摘要和关键词建议。
5. 用户编辑并确认采纳结果。
6. 系统将采纳结果写入笔记元数据或摘要区。

### 8.5 知识点检索

1. 用户输入关键词。
2. 用户可选择课程、章节、标签、内容类型等筛选条件。
3. 系统检索笔记、错题、标签、摘要和知识节点。
4. 系统返回相关结果，并展示所属知识点和匹配片段。
5. 用户点击结果，跳转到目标笔记、错题或内容片段。

## 12. 非功能需求

### 12.1 可用性

1. 系统应提供清晰的课程、章节、知识点导航。
2. 笔记创建、归档、检索和复习路径应尽量短。
3. AI 相关功能应作为增强能力，不应阻塞基础学习流程。

### 12.2 性能

1. 常规页面应在可接受时间内完成加载。
2. 课程内笔记、错题和评论数量增长后，列表页应支持分页或懒加载。
3. 搜索应在课程级数据规模下快速返回结果。
4. 图片和附件应有合理大小限制，避免影响加载速度。

### 12.3 安全性

1. 用户密码不得明文存储。
2. 接口应进行身份认证和权限校验。
3. 个人笔记和课程内共享内容应严格区分访问权限。
4. 文件上传应限制类型和大小，避免恶意文件。
5. AI 接口密钥等敏感配置不得暴露到前端。

### 12.4 数据一致性

1. 删除章节或知识点前，应提示其下关联笔记、错题和子节点数量。
2. 移动知识节点时，应保持其关联内容不丢失。
3. 内容发布、纠错采纳和版本记录应保持一致。

### 12.5 可维护性

1. 系统应采用前后端分离架构。
2. 业务模块应按用户、课程、知识树、笔记、错题、协作、AI、检索拆分。
3. 关键数据结构和接口应有文档说明。
4. AI 模块、检索模块应设计为可替换或可关闭。

### 12.6 可扩展性

1. 系统应支持从单课程扩展到多课程。
2. 搜索能力应支持从基础关键词检索扩展到全文检索和向量检索。
3. AI 能力应支持从摘要和标签扩展到知识点推荐、相似错题推荐。

## 13. 技术路线约束

项目拟采用前后端分离架构。

| 层次 | 建议方案 |
| --- | --- |
| 前端 | Vue 或 React，用于课程页面、笔记编辑器、知识树、共享互动和搜索页面 |
| 后端 | FastAPI、Flask 或 Spring Boot，用于用户管理、课程管理、笔记存储、协作逻辑、AI 调用和搜索服务 |
| 数据库 | MySQL 或 PostgreSQL，用于存储用户、课程、章节、笔记、标签和互动记录 |
| 搜索 | MVP 可先使用数据库关键词检索，后续可接入全文检索引擎 |
| AI | 初期接入大模型接口实现摘要生成和关键词提取，后续扩展推荐能力 |

## 14. 优先级划分

| 优先级 | 说明 | 示例 |

## 15. 验收标准

系统达到以下条件时，可认为课程项目原型满足基本验收要求：

1. 用户可以注册、登录并进入系统。
2. 用户可以创建或加入课程。
3. 课程维护者可以创建章节和知识点，形成课程知识树。
4. 用户可以创建一篇包含文本、代码、公式和图片的笔记。
5. 笔记可以归档到指定章节或知识点。
6. 用户可以录入错题，并按章节、题型或标签筛选。
7. 用户可以将笔记共享到课程内。
8. 课程成员可以对共享笔记点赞、评论、补充或纠错。
9. 系统可以对笔记生成摘要和关键词标签，且用户可以人工确认。
10. 用户可以通过关键词、章节、知识点和标签检索笔记或错题。
11. 搜索结果可以展示匹配片段和所属知识节点。
12. 系统具备基本文档，包括系统设计文档、数据库设计文档、用户说明文档和演示材料。

## 17. 风险与应对措施

| 风险 | 说明 | 应对措施 |
| --- | --- | --- |
| 技术实现风险 | 富文本编辑器对公式、代码块、图片和思维导图的支持可能存在兼容性问题 | 优先采用成熟开源编辑器组件，先保证文本、代码、公式和图片能力 |
| AI 接口风险 | AI 调用可能成本高、响应慢或结果不稳定 | 将 AI 设计为可选增强模块，失败时不影响核心功能 |
| 项目范围过大 | 编辑、协作、检索和 AI 模块同时开发可能导致进度压力 | 优先完成核心闭环，再逐步扩展高级功能 |
| 协作内容质量风险 | 用户上传内容可能重复、冗余或存在错误 | 通过点赞排序、评论纠错、补充建议、版本记录和维护者审核缓解 |
| 数据样本不足 | 缺少真实课程笔记时，系统功能难以充分展示 | 准备模拟课程数据，并邀请少量同学试用反馈 |
| 检索效果不足 | 基础关键词检索可能无法准确定位知识点 | 先用结构化节点和标签提升精度，后续引入全文检索或向量检索 |

## 18. 开放问题

1. 是否需要教师/助教参与内容审核，还是仅由学生小组维护。
2. 课程加入方式采用邀请码、公开搜索，还是两者都支持。
3. 思维导图内容以图片上传、嵌入编辑器组件，还是独立数据结构存储。
4. AI 接口使用本地模型、第三方 API，还是预留统一适配层。
5. 笔记版本记录需要做到全文差异对比，还是仅保存历史快照。
6. MVP 是否需要支持 Word、Markdown 等外部文件导入。
