# NoteWeave 架构文档

## 1. 架构目标

NoteWeave 当前架构服务于一个笔记优先的学习 Demo：

```text
用户写入笔记 -> AI 解析 -> 自动课程/知识点归类 -> 生成检索片段 -> 笔记问答
```

系统只通过 API 调用大模型，不引入 MoDora 的 OCR、本地模型、GPU 调度、PDF bbox、实验评测等重依赖。AI 失败时使用 fallback，保证演示稳定。

## 2. 产品闭环

```text
Landing
  -> 登录/注册
  -> 添加笔记或导入 PDF/DOCX/Markdown
  -> /api/notes/ingest 或 /api/notes/import
  -> AIAssistService.classify_note
  -> 内部课程分类 + 知识点节点
  -> search_chunks
  -> 共享/评论/点赞
  -> /api/notes/ask
```

课程在当前版本中不是用户管理对象，而是 AI 自动归类后的内部分类容器。前端可以展示“AI 分类”，但不提供新建课程、加入课程、课程成员管理入口。

## 3. 从 MoDora 借鉴什么

MoDora 的可借鉴点是流程，而不是依赖：

| MoDora 思路 | NoteWeave 落地 |
| --- | --- |
| 文档解析 | `AIAssistService.classify_note` 对笔记生成摘要、标签、课程名、知识点名 |
| CCTree / 层级结构 | 使用 `courses` + `knowledge_nodes` 保存 AI 分类和知识点路径 |
| 检索增强问答 | 使用 `search_chunks` 召回可见笔记片段，再交给模型回答 |
| Prompt 分任务组织 | 摘要、标签、归类、问答分别封装为 AI service 方法 |
| 可降级链路 | 远程模型不可用时使用本地关键词 fallback |

## 4. 不引入的 MoDora 能力

| 能力 | 当前处理 |
| --- | --- |
| OCR / PDF 版面视觉解析 | 不引入，MVP 只抽取 PDF 文本 |
| 本地模型 / GPU | 不引入，只使用远程模型 API |
| ChromaDB / 大型向量库 | 不引入，先用 SQLite 搜索片段 |
| 实验 CLI / 数据集评测 | 不进入产品主链路 |
| 复杂图像处理 | 后续只做附件上传和展示 |

## 5. 技术栈

| 层 | 当前方案 |
| --- | --- |
| 前端 | Vue 3 + Vite + TypeScript + lucide icons |
| 后端 | FastAPI + Pydantic |
| 数据库 | SQLite，便于 demo 和单机部署 |
| Python 环境 | uv |
| AI | OpenAI-compatible Chat Completions API，可关闭 |
| 部署 | Nginx 静态前端 + systemd 后端服务 |

## 6. 后端模块

```text
backend/src/noteweave/
  api/
    app.py              # FastAPI 路由与当前 demo 业务编排
    schemas.py          # 请求模型
  core/
    ai.py               # 摘要、标签、自动归类、问答
    database.py         # SQLite schema 与轻量 DB helper
    security.py         # 密码和 token
    settings.py         # 环境配置
```

当前代码仍保留旧课程 API 以兼容已有数据和测试，但新产品主入口是：

| API | 用途 |
| --- | --- |
| `POST /api/notes/ingest` | 添加笔记并自动归类 |
| `POST /api/notes/import` | 导入 PDF、Word `.docx`、Markdown，抽取文本后自动归类 |
| `GET /api/notes/feed` | 返回用户自己的笔记和全站共享笔记 |
| `POST /api/notes/ask` | 基于可见笔记检索上下文并问答 |
| `GET /api/admin/overview` | 管理员只读系统概览 |
| `GET /api/courses` | 作为 AI 分类列表读取 |
| `GET /api/notes` | 按内部分类读取笔记 |
| `POST /api/reactions` | 点赞/收藏 |
| `GET/POST /api/comments` | 评论 |

## 7. 数据模型

当前 demo 使用已有表结构，并重新解释部分表的产品含义：

| 表 | 当前含义 |
| --- | --- |
| `users` | 普通用户/管理员账号，`system_role` 只使用 `user` / `admin` |
| `courses` | AI 自动生成的课程分类容器 |
| `course_members` | 兼容旧权限检查的内部授权表，仍可能保存 `student` 等旧课程角色，但不暴露为产品角色 |
| `knowledge_nodes` | AI 自动生成的知识点/主题节点 |
| `notes` | 核心内容对象 |
| `note_versions` | 笔记版本快照 |
| `comments` | 笔记评论 |
| `reactions` | 点赞、收藏 |
| `ai_results` | AI 摘要/标签建议 |
| `search_chunks` | 问答和搜索使用的笔记片段 |
| `audit_logs` | 关键操作记录 |

## 8. AI 编排

### 8.1 自动归类

`classify_note(title, content, tags)` 返回：

```json
{
  "course_name": "计算机科学",
  "node_title": "Dijkstra",
  "summary": "这条笔记说明 Dijkstra 适用于非负权图。",
  "tags": ["最短路", "图算法"],
  "source": "remote"
}
```

如果远程模型不可用：

1. `fallback_summary` 截取正文摘要。
2. `fallback_tags` 从文本中抽取关键词。
3. `infer_course_name` 根据关键词粗略判断课程分类。

### 8.2 笔记问答

问答流程：

1. 根据用户可访问的内部课程分类读取 `search_chunks`。
2. 通过关键词匹配召回相关笔记片段。
3. 有远程模型时，把问题和片段交给模型回答。
4. 没有远程模型时，返回相关片段摘要。
5. 前端展示答案和上下文片段。

### 8.3 文件导入

文件导入借鉴 MoDora 的“先解析文档，再进入结构化和问答链路”，但实现保持轻量：

| 文件类型 | 解析方式 |
| --- | --- |
| Markdown | 直接按文本解码 |
| Word `.docx` | 使用标准库读取 `word/document.xml` 文本节点 |
| PDF | 使用轻量 `pypdf` 抽取页面文本 |

解析出的文本会进入与手写笔记相同的 `classify_note`、内部分类、`search_chunks` 和问答流程。当前不支持 `.doc` 二进制 Word、OCR 和复杂 PDF 版面理解。

## 9. 前端架构

```text
frontend/src/
  App.vue
  components/
    LandingPage.vue
    WorkspacePage.vue
  services/
    api.ts
  styles/
    main.css
  types.ts
```

界面方向：

1. Landing 介绍笔记核心、AI 自动归类、笔记问答。
2. 工作台采用三栏结构：左侧账号和 AI 分类，中间笔记编辑/文件导入与笔记流，右侧解析结果、问答和当前笔记。
3. 管理员在侧栏看到只读系统概览，包括用户数、共享笔记、导入文件、AI 结果和模型配置状态。
4. 不出现新建课程、加入课程、课程成员角色管理等入口。
5. 视觉参考 Obsidian/Notion：安静、克制、高级、可扫描。

## 10. 部署架构

```text
Nginx
  /noteweave/        -> Vue dist
  /noteweave/api/    -> FastAPI 127.0.0.1:8000/api/
  /noteweave/health  -> FastAPI /health

systemd
  noteweave-backend.service
```

部署后应验证：

```bash
curl -I http://wu-uk.com/noteweave/
curl -sS http://wu-uk.com/noteweave/health
```

## 11. 后续演进

1. 把旧课程 API 从主产品语义中逐步剥离，只保留内部分类服务。
2. 增加附件上传入口，并让上传内容进入笔记摄取流程。
3. 增加管理员页面，用于 AI 配置、用户和数据维护。
4. 如 demo 需要更强问答，再引入托管向量服务或轻量 embedding，而不是本地重依赖。
